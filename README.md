# Tongumble

Genox 인계와 현재 구현의 통합 기준은 [GENOX_SPEC_HANDOFF.md](GENOX_SPEC_HANDOFF.md)다. 이 README와 코드의 차이가 있으면 실제 코드와 최신 [PLAYTEST.md](PLAYTEST.md)를 기준으로 삼는다.

Three.js·Rapier 기반 3D 개구리 로프 액션의 생태계 코스 프로토타입이다. 먹이에 혀를 걸어 진자 스윙을 만들고, Space로 파리를 먹으면 파리 위치까지 짧은 포물선 대쉬를 한다. 도착 뒤 관성을 이어 다음 먹이에 다시 연결한다. 기본 코스는 10개 생태계를 거치는 약 1540m 상승 코스다.

현재 새 코스 `ecosystem-main-v5`는 1540m·10개 생태계로 올라간다. 기존 지형의 높이와 좌우 폭을 각각 두 배로 키우고, 우물 반지름은 8.6m로 확장했다. 넓어진 공간을 채우도록 중간 발판 174개와 이동 먹이 경로를 추가해 221개 진행 구간을 만든다. 굵어진 나무와 생태계별 원경 배치도 월드 크기에 맞췄다. 혀 사거리는 12m를 유지한다. v2·v3·v4 저장은 각 원래 코스에서 계속 열린다. [레벨 디자인 스펙](LEVEL_DESIGN_SPEC.md)과 `src/game/ecosystem-v5.ts`가 기준이다. 전체 코스 사람 플레이 난이도는 아직 검증하지 않았다.

## 플레이와 실행

공개 플레이 페이지: https://cheonyeon0316.github.io/frog-rope-ascent/

`main` 브랜치에 푸시하면 GitHub Actions가 빌드하고 GitHub Pages에 배포한다.

Windows 패키지의 `START-GAME.cmd`는 배포 게임을 **http://127.0.0.1:5280/** 에 연다. 개발은 포함된 `DEVELOP.cmd` 또는 이 폴더의 `pnpm install --frozen-lockfile`, `pnpm dev`를 사용하고 **http://127.0.0.1:5173/** 에 접속한다. `pnpm build:html`은 26개 GLB 에셋을 포함한 단일 `frog-ascent.html`을 생성해 파일로 직접 열 수 있다.

메뉴에서 **생태계 오르기**가 새 v5 맵을 시작한다. 기존 저장은 각 원래 맵의 위치·속도·연결을 그대로 복원한다. 이전 맵의 좌표를 새 지형으로 임의로 옮기지 않는다. 새 게임은 기존의 새 시작 확인 절차를 사용하므로 이전 진행을 보관하려면 설정의 저장 내보내기를 사용한다. `garden-main-v1`과 `ecosystem-main-v2`부터 `ecosystem-main-v5`까지 백업을 가져올 수 있다.

| 입력 | 동작 |
|---|---|
| 마우스 이동 | 먹이 조준. 연결 가능하면 조준점과 먹이에 원 표시 |
| 왼쪽 버튼 누르기 | 혀 연결·홀드 유지 |
| 왼쪽 버튼 놓기 | 혀를 해제하고 기존 관성을 유지하며 약한 해제 보너스를 받음. 다시 눌러 다음 먹이에 연결 |
| WASD / 방향키 | 지면 이동·스윙 방향 조절·약한 공중 보정 |
| Space / Shift | 지면 점프. 줄에 매달린 동안 Space는 파리를 먹고 해당 위치까지 대쉬. 연결하지 않은 물 안에서는 Space 홀드 상승 수영 / Shift 잠수 |
| 우클릭 드래그 | 카메라 회전. 혀 홀드와 동시에 사용 가능 |
| Esc / Ⅱ | 물리까지 일시정지 |

혀 사거리는 연습·이전 코스에서 10m, 새 v5 코스에서 12m이며 지형을 통과하지 않는다. 감기나 자동 끌어올리기는 없다. 먼저 12m 연습 코스에서 점프 후 연결·스윙·Space 먹기 대쉬·재연결을 익힌다. 표준 패드는 왼쪽 스틱 이동, 오른쪽 스틱 시점, RT 연결, A 점프/먹기 대쉬, Start 일시정지이며 실기기 검증이 남아 있다. 터치 입력은 없다.

지상 점프 속도는 7.5m/s로 약 1.5m 높이까지 오른다(이전 약 0.55m). 연결 중 Space를 새로 누르면 먹이를 소비하고 얕은 포물선을 따라 먹이 위치까지 대쉬한다. 0.1~1.7초 동안 거리에 맞춰 이동하며, 도착 목표 속도를 낮춰 착지·재연결 선택을 이어간다. 목표점 이후에도 운동량은 남는다. 일반적인 마우스 혀 해제도 관성을 유지하면서 먹이 방향으로 약한 보너스를 준다. 카메라는 여러 가로 위치에서 장애물을 확인해 지형 앞에서 멈추고, 끝까지 가림이 남으면 화면을 가리는 지형만 반투명하게 만든다. 테마 전환은 카메라를 자동 회전시키지 않아 WASD 방향 기준을 그대로 유지한다. 연결 없이 공중에서 Space를 눌러도 추가 점프는 하지 않는다.

## 생태계와 실패의 범위

### 풀숲과 개구리 아트

개구리 크기를 줄여 지형과 비례를 맞추고, 현재는 7본 리그의 개구리 GLB를 플레이어 모델로 사용한다. Idle·Jump·Dash 클립을 실제 입력 상태에 연결했다. 생태계 코스에서는 과밀했던 절차 잔디를 끄고, GLB 풀 군락 네 개를 드문 위치에 배치한다. 연못·연잎·갈대·뿌리·자갈, 초원 버섯·들꽃, 나뭇가지·암릉·구름·별 발판도 GLB 모델이 씬에 보이도록 연결했다. 8종 먹이는 각 먹이 앵커에서 해당 GLB로 표시하며, 코스 데이터가 충돌을 계속 담당한다.

| 높이 | 지형 | 먹이 |
|---|---|---|
| 0–105m | 작은 연못·풀잎 | 초파리 |
| 105–245m | 거대한 풀숲·줄기와 잎 | 초파리·파리 |
| 245–420m | 바위 골짜기·돌턱 | 파리·풍뎅이 |
| 420–630m | 거대한 꽃·꽃받침과 꽃잎 | 꽃가루·벌 |
| 630–840m | 오래된 나무·가지와 수관 | 벌·나방 |
| 840–1015m | 바위산·능선과 움푹한 암반 | 풍뎅이·나방 |
| 1015–1155m | 구름 바다·구름 덩어리 | 이슬 |
| 1155–1260m | 별의 길·별 모양 발판 | 별가루 |
| 1260–1400m | 뿌리의 안개 미궁·엇갈린 뿌리와 가지 | 나방·이슬 |
| 1400–1540m | 새벽 꽃섬·갈라진 꽃잎과 수술 | 꽃가루·별가루 |

각 지형은 서로 다른 평면 위치에 있다. 구역 하단에는 뿌리, 암반, 꽃받침, 가지 갈림, 구름, 운석 등 테마에 맞는 실제 충돌 지형이 있어 지역 낙하를 받아준다. 새 뿌리 미궁은 좁은 아치·엇갈린 가지·움직이는 지름길 먹이로 경로 선택을 만든다. 새벽 꽃섬은 안쪽 나선과 바깥 꽃잎 갈래를 거쳐 별 정상에 이른다. `platformMesh`의 삼각형 데이터를 렌더러와 물리 엔진이 공유한다. 첫 연못 지면은 `landscapeMesh`를 공유하고 정상은 실제 별 모양 충돌을 사용한다. GLB는 [에셋 상태 문서](assets-source/PRODUCTION_STATUS.md)에 기록한 1차 제작물을 씬의 실제 시각 모델로 사용하며, 충돌은 검증된 코스 지형을 유지한다.

다음 생태계로 넘어가는 바깥 경로에서 실패하면 이전 생태계나 더 아래로 떨어질 수 있다. 안전은 높이·방문 기록에 따른 순간이동이 아니라 지형이 제공한다. 진입구·바깥 경계로 빠져나가면 큰 손실이 가능하다. 현재 구역 안의 먹이에 다시 연결해 재도전한다.

각 전환 구간의 금빛 원 먹이는 다음 지형으로 향하는 대쉬 목적지다. 먹이 위치에서 추진이 마무리되고 관성이 남아 지형 착지나 재연결로 이어진다. 새 뿌리 미궁과 새벽 꽃섬에는 선택형 이동 먹이 길을 두어 정규 발판과 다른 경로를 시도할 수 있다. 브라우저 검사는 10개 생태계의 회복·먹이 입력을 확인한다. 전체 완주와 사람의 구역별 난이도 평가는 별도 검증 대상이다.

먹이 여덟 종류는 실루엣·재질·크기를 구분한다. 벌은 빠른 가로 이동, 꽃가루는 느린 부유, 나방은 더 큰 세로 이동을 사용한다. 잡힌 먹이는 대쉬 중 회수되어 삼켜진다. 별도의 강화·독·전투 시스템은 없다. 회수 0.32초, 삼키기 0.22초, 활성 플레이 시간 기준 재생성 3초다. 일반 수동 혀 해제는 먹이를 회수하고 기존 속도를 보존하면서 먹이 쪽으로 약한 보너스를 더한다.

## 저장과 설정

메인 진행은 실제 위치·속도·혀 연결·시간·먹이 재생성·이동 위상을 IndexedDB에 자동 저장한다. 발판과 구역 진입은 체크포인트가 아니다. 같은 브라우저와 서버 주소를 사용하고, 다른 PC/주소로 옮길 때는 **설정 → 저장 내보내기/가져오기**를 사용한다. 연습은 메인 저장을 덮어쓰지 않는다. 연결 상태로 재개하면 왼쪽 버튼을 다시 눌러야 물리가 진행된다.

설정에서 토글 연결·조준 보조·음량·몸의 보조 흔들림·그래픽 품질을 변경한다. 저장 이전 방법은 [이전 안내](tools/transfer-guide.md)를, 역사와 보조 맥락은 [인수인계](../../HANDOFF.md)를 확인한다. 현재 구현을 이어받을 때는 [통합 인계 문서](GENOX_SPEC_HANDOFF.md)가 우선이다.

## Codex 개발 워크플로

이 프로젝트에는 Cursor 공식 저장소의 pstack 59개 Agent Skill이 `.agents/skills/`에 설치되어 있다. 새 Codex 작업에서 `$poteto-mode`로 시작하거나 `$how`, `$tdd`, `$technical-writing`처럼 필요한 스킬을 직접 지정할 수 있다. 설치 목록과 파일 해시는 `skills-lock.json`에 기록되어 있다. 원본은 Cursor 플러그인이며 Codex에서는 프로젝트 Skill로 불러온다. Codex 도구에 맞춘 호출·모델 규칙은 [PSTACK-CODEX.md](PSTACK-CODEX.md)에 정리했다. 현재 사용자 환경은 `~/.agents/pstack-models.md`에서 모든 역할이 대화 모델을 상속하고 large/xhigh 예산을 사용한다. pstack 출처와 라이선스는 [PSTACK-NOTICE.md](PSTACK-NOTICE.md)에 기록했다.

## 검사와 현재 한계

```powershell
pnpm test             # 66개 물리·저장·코스 회귀 검사
pnpm build            # 타입 검사·배포 빌드
pnpm test:ecosystem   # 새 생태계의 착지·먹이 연결/먹기·화면 (dev 서버)
pnpm test:assets      # 환경 GLB 17종·소품 18개 배치와 기존 캐릭터 복원 (dev 서버)
pnpm test:browser     # 기본 입력·일시정지·저장·작은 창
pnpm test:transfer    # 독립 브라우저 간 저장 내보내기/가져오기
pnpm test:feeding     # 회수·삼키기·재생성
pnpm test:camera      # 혀 홀드 중 시점 회전
pnpm test:dash        # 일반 혀 해제와 관성·중력
pnpm test:launch      # 실제 Space 점프/파리 목표 대쉬·재연결·저장 복원 (dev 서버)
pnpm test:gimmicks    # 이전 정원의 이동 파리·수영·탄성 잎 보존
pnpm test:refuges     # 이전 정원의 쉼터 보존
```

브라우저 도구는 Chrome/Edge를 탐색한다. 필요하면 `CHROME_PATH`, `GAME_URL`을 지정한다. 생태계 기능 검사는 구역별 낙하 시작 상태를 사용한다. 자동으로 10개 구역의 회복면, 먹이 연결·먹기, v4 이전 저장 호환을 확인한다. **지면부터 1540m 완주, 구역 전환의 사람 플레이 난이도와 추락 후 재도전 의지는 아직 검증하지 않았다.** 새 길의 조형과 실패율은 플레이테스트 후 다듬어야 한다. 번들 크기 경고도 남아 있다.

이 버전은 절차적 지형과 모델로 구조를 검증하는 프로토타입이다. 최종 아트·음악·온라인 순위·리플레이는 제작되지 않았다. 검증 기록과 캡처는 [PLAYTEST.md](PLAYTEST.md)에 있다.

## 코드

- `src/game/ecosystem.ts`: 새 생태계·먹이·굴곡 지형·상승 경로
- `src/game/course.ts`, `legacy-course.ts`: 맵 선택·이전 저장의 원래 코스
- `src/game/environment.ts`: 렌더/물리 공통 지형·별·구름 메시, 이동·물
- `src/game/simulation.ts`: 120Hz 물리·연결·먹기·충돌·낙하
- `src/render/garden.ts`: 모델·지형·테마 하늘·카메라·애니메이션
- `src/game/storage.ts`, `backup.ts`: 저장과 기기 이전
- `src/ui/interface.ts`, `src/main.ts`: 메뉴·HUD·상태·피드백

참고 게임의 모델·UI·음원을 가져오지 않았다. 배포 라이브러리의 라이선스는 패키지에 포함한다.
