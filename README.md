# 혀끝까지 — 연못에서 별까지

Genox 인계와 현재 구현의 통합 기준은 [GENOX_SPEC_HANDOFF.md](GENOX_SPEC_HANDOFF.md)다. 이 README와 코드의 차이가 있으면 실제 코드와 최신 [PLAYTEST.md](PLAYTEST.md)를 기준으로 삼는다.

Three.js·Rapier 기반 3D 개구리 로프 액션의 생태계 코스 프로토타입이다. 먹이에 혀를 걸고 진자 스윙을 만든 뒤 놓으며 먹기 대쉬·재연결로 상승한다. 하나의 나무를 둘러싸는 기존 정원 대신, 옆으로 이동하며 여덟 지형을 거치는 180m 코스를 사용한다.

## 플레이와 실행

공개 플레이 페이지: https://cheonyeon0316.github.io/frog-rope-ascent/

`main` 브랜치에 푸시하면 GitHub Actions가 빌드하고 GitHub Pages에 배포한다.

Windows 패키지의 `START-GAME.cmd`는 배포 게임을 **http://127.0.0.1:5280/** 에 연다. 개발은 포함된 `DEVELOP.cmd` 또는 이 폴더의 `pnpm install --frozen-lockfile`, `pnpm dev`를 사용하고 **http://127.0.0.1:5173/** 에 접속한다. HTML 파일을 직접 열지 않는다.

메뉴에서 **생태계 오르기**가 새 맵을 시작한다. 기존 저장은 **이전 정원 이어가기**로 원래 맵의 위치·속도·연결을 그대로 복원한다. 이전 맵의 좌표를 새 지형으로 임의로 옮기지 않는다. 새 게임은 기존의 새 시작 확인 절차를 사용하므로 이전 진행을 보관하려면 설정의 저장 내보내기를 사용한다. `garden-main-v1`은 이전 정원, `ecosystem-main-v2`는 새 생태계이며 두 맵의 백업을 모두 가져올 수 있다.

| 입력 | 동작 |
|---|---|
| 마우스 이동 | 먹이 조준. 연결 가능하면 조준점과 먹이에 원 표시 |
| 왼쪽 버튼 누르기 | 혀 연결·홀드 유지 |
| 왼쪽 버튼 놓기 | 먹이 회수·삼키기·먹이 방향 대쉬, 다음 먹이에 재연결 |
| WASD / 방향키 | 지면 이동·스윙·약한 공중 보정 |
| Space / Shift | 지면 점프. 혀 연결 중 Space는 강한 먹기 대쉬. 연결하지 않은 물 안에서는 Space 홀드 상승 수영 / Shift 잠수 |
| 우클릭 드래그 | 카메라 회전. 혀 홀드와 동시에 사용 가능 |
| Esc / Ⅱ | 물리까지 일시정지 |

혀 사거리는 10m이며 지형을 통과하지 않는다. 감기나 자동 끌어올리기는 없다. 먼저 12m 연습 코스에서 점프 후 연결·왕복 운동에 맞춘 스윙·먹기 도약을 익힌다. 표준 패드는 왼쪽 스틱 이동, 오른쪽 스틱 시점, RT 연결, A 점프, Start 일시정지이며 실기기 검증이 남아 있다. 터치 입력은 없다.

지상 점프 속도는 7.5m/s로 약 1.5m 높이까지 오른다(이전 약 0.55m). **매달린 채 Space**를 새로 누르면 먹이를 먹고 그 위치로 유도 대쉬한다. 이동시간은 남은 거리에 비례하며 0.1~1.7초 범위, 시작 속도 8m/s·순항 기준 7.2m/s·도착 목표 속도 3m/s다. 진행 후반부에서 감속하고 옆방향 스윙 속도의 절반을 일부 보존하며 전체 속도는 16m/s로 제한한다. 추진은 목표 먹이에서 끝나고, 이후 개구리는 남은 물리 관성으로 움직인다. 화면 연출은 혀와 먹이를 입 쪽으로 당기며 몸과 다리 포즈를 대시에 맞추도록 구현했으며, 부드러움에 대한 시각 QA는 진행 중이다. Space를 계속 누르거나 키가 반복되어도 새로 연결한 먹이를 자동으로 먹지 않으며, 떼고 다시 눌러야 다음 강한 대시가 나간다. 다음 먹이는 왼쪽 버튼을 놓았다 다시 눌러 연결한다. 토글 설정과 패드 A도 같은 문맥 동작을 사용한다. 연결 없이 Space를 눌러도 공중 점프는 하지 않는다.

## 생태계와 실패의 범위

### 풀숲과 개구리 아트

개구리는 화면에서 36% 작게 조정해 주변 지형과 크기를 맞췄다. 일곱 실루엣 풀은 이전보다 낮고 가늘게 줄이고, 발판과 먹이 주변에는 여백을 둔다. 연못과 풀숲 가장자리에 작은 관목을 무리 지어 배치하고 꽃 구역에는 야생화를 흩뿌린다. 수면이 땅에 묻히지 않도록 연못 자리를 낮춘 오목한 물가로 만들었다. 분지의 바닥은 삼각형 굴곡 지형과 연결되는 층진 절벽으로 만들고, 평평한 바닥 덧면과 긴 지지 기둥을 제거했다. 바위 구역의 독립된 대형 바위는 덜어내고 작은 암석 무리를 남겼다. 진입 경사는 낮추되 바깥쪽 능선은 보존해 구역 사이 낙하 위험을 유지한다. 개구리는 넓은 몸통·주둥이·황금빛 눈·밝은 목과 굵은 뒷허벅지를 가진 저폴리 모델이며, 앞·뒷다리를 따로 움직인다. 달리기·수영·줄타기·상승·낙하·먹기 대쉬에 따라 다리를 접고 뻗는다.

| 높이 | 지형 | 먹이 |
|---|---|---|
| 0–15m | 작은 연못·풀잎 | 초파리 |
| 15–35m | 거대한 풀숲·줄기와 잎 | 초파리·파리 |
| 35–60m | 바위 골짜기·돌턱 | 파리·풍뎅이 |
| 60–90m | 거대한 꽃·꽃받침과 꽃잎 | 꽃가루·벌 |
| 90–120m | 오래된 나무·가지와 수관 | 벌·나방 |
| 120–145m | 바위산·능선과 움푹한 암반 | 풍뎅이·나방 |
| 145–165m | 구름 바다·구름 덩어리 | 이슬 |
| 165–180m | 별의 길·별 모양 발판 | 별가루 |

각 지형은 서로 다른 평면 위치에 있다. 구역 안쪽에는 낮은 바닥과 높은 가장자리가 연속된 굴곡 지형이 있어 실패를 해당 생태계 안에서 받아준다. 꽃받침·구름·별 구역의 바닥은 둥근 윤곽이고, 나무의 발판은 실제 충돌하는 가지로 줄기에 연결된다. 바위와 꽃 줄기도 충돌 지형이다. 지형의 삼각형 데이터를 렌더러와 물리 엔진이 공유한다. 구름 발판은 실제 볼록 덩어리, 별 발판은 실제 별 모양 충돌을 사용한다.

다음 생태계로 넘어가는 바깥 경로에서 실패하면 이전 생태계나 더 아래로 떨어질 수 있다. 안전은 높이·방문 기록에 따른 순간이동이 아니라 지형이 제공한다. 진입구·바깥 경계로 빠져나가면 큰 손실이 가능하다. 현재 구역 안의 먹이에 다시 연결해 재도전한다.

강화된 이동에 맞춰 각 전환 구간에 두 겹의 금빛 원으로 표시한 연결용 먹이를 두었다. 상위 먹이는 다음 발판 방향으로 배치하고, 움직이는 먹이가 가지나 발판 안에 들어가지 않도록 궤도를 검사한다. 지형 진입구는 이전 생태계에서 오는 도약 방향을 향한다. 꽃의 진입부를 덮던 꽃잎은 열고, 구름과 별의 평면 간격도 줄였다. 7개 전환 구간은 각 구역의 마지막 발판에서 Space 대쉬로 다음 생태계에 도달하는 물리 검사를 통과했다.

먹이 여덟 종류는 실루엣·재질·크기를 구분한다. 벌은 빠른 가로 이동, 꽃가루는 느린 부유, 나방은 더 큰 세로 이동을 사용한다. 모든 먹이는 잡히면 움직임이 멈추고 동일한 로프·먹기 대쉬 규칙을 따른다. 별도의 강화·독·전투 시스템은 없다. 회수 0.32초, 삼키기 0.22초, 활성 플레이 시간 기준 재생성 3초다. 마우스 해제는 기존 속도에 먹이 방향 3.5m/s를 더하는 짧은 도약이고, Space는 거리에 따라 시간이 정해진 목표 지점 유도 대쉬를 사용한다.

## 저장과 설정

메인 진행은 실제 위치·속도·혀 연결·시간·먹이 재생성·이동 위상을 IndexedDB에 자동 저장한다. 발판과 구역 진입은 체크포인트가 아니다. 같은 브라우저와 서버 주소를 사용하고, 다른 PC/주소로 옮길 때는 **설정 → 저장 내보내기/가져오기**를 사용한다. 연습은 메인 저장을 덮어쓰지 않는다. 연결 상태로 재개하면 왼쪽 버튼을 다시 눌러야 물리가 진행된다.

설정에서 토글 연결·조준 보조·음량·몸의 보조 흔들림·그래픽 품질을 변경한다. 저장 이전 방법은 [이전 안내](tools/transfer-guide.md)를, 역사와 보조 맥락은 [인수인계](../../HANDOFF.md)를 확인한다. 현재 구현을 이어받을 때는 [통합 인계 문서](GENOX_SPEC_HANDOFF.md)가 우선이다.

## Codex 개발 워크플로

이 프로젝트에는 Cursor 공식 저장소의 pstack 59개 Agent Skill이 `.agents/skills/`에 설치되어 있다. 새 Codex 작업에서 `$poteto-mode`로 시작하거나 `$how`, `$tdd`, `$technical-writing`처럼 필요한 스킬을 직접 지정할 수 있다. 설치 목록과 파일 해시는 `skills-lock.json`에 기록되어 있다. 원본은 Cursor 플러그인이며 Codex에서는 프로젝트 Skill로 불러온다. Codex 도구에 맞춘 호출·모델 규칙은 [PSTACK-CODEX.md](PSTACK-CODEX.md)에 정리했다. 현재 사용자 환경은 `~/.agents/pstack-models.md`에서 모든 역할이 대화 모델을 상속하고 large/xhigh 예산을 사용한다. pstack 출처와 라이선스는 [PSTACK-NOTICE.md](PSTACK-NOTICE.md)에 기록했다.

## 검사와 현재 한계

```powershell
pnpm test             # 64개 물리·저장·코스 회귀 검사
pnpm build            # 타입 검사·배포 빌드
pnpm test:ecosystem   # 새 생태계의 착지·먹이 연결/먹기·화면 (dev 서버)
pnpm test:browser     # 기본 입력·일시정지·저장·작은 창
pnpm test:transfer    # 독립 브라우저 간 저장 내보내기/가져오기
pnpm test:feeding     # 회수·삼키기·재생성
pnpm test:camera      # 혀 홀드 중 시점 회전
pnpm test:dash        # 먹기 도약
pnpm test:launch      # 실제 Space 점프/강한 대쉬·키 반복·토글·저장·풀숲 진입 (dev 서버)
pnpm test:gimmicks    # 이전 정원의 이동 파리·수영·탄성 잎 보존
pnpm test:refuges     # 이전 정원의 쉼터 보존
```

브라우저 도구는 Chrome/Edge를 탐색한다. 필요하면 `CHROME_PATH`, `GAME_URL`을 지정한다. 생태계 기능 검사는 구역별 낙하 시작 상태를 사용한다. 자동으로 구역 안 착지·이전 구역으로 손실·먹이 연결과 재생성·36개 진입 먹이의 가시성 및 기존 저장 호환을 확인한다. **지면부터 180m 완주, 각 구역 전환의 사람 플레이 난이도와 추락 후 재도전 의지는 아직 검증하지 않았다.** 조형·연결 구간·실패율은 플레이테스트 후 다듬어야 한다. 번들 크기 경고도 남아 있다.

이 버전은 절차적 지형과 모델로 구조를 검증하는 프로토타입이다. 최종 아트·음악·온라인 순위·리플레이는 제작되지 않았다. 검증 기록과 캡처는 [PLAYTEST.md](PLAYTEST.md)에 있다.

## 코드

- `src/game/ecosystem.ts`: 새 생태계·먹이·굴곡 지형·상승 경로
- `src/game/course.ts`, `legacy-course.ts`: 맵 선택·이전 저장의 원래 코스
- `src/game/environment.ts`: 렌더/물리 공통 지형·별·구름 메시, 이동·물
- `src/game/simulation.ts`: 120Hz 물리·연결·먹기·충돌·낙하
- `src/render/garden.ts`: 모델·지형·테마 하늘·카메라·애니메이션
- `src/game/storage.ts`, `backup.ts`: 저장과 기기 이전
- `src/ui/interface.ts`, `src/main.ts`: 메뉴·HUD·상태·피드백

참고 게임의 모델·UI·음원을 가져오지 않았다. 배포 라이브러리의 라이선스는 패키지에 포함한다.
